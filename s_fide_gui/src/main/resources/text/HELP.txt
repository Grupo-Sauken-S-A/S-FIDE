# S-FiDE - Guía Rápida

Sistema de Firma Digital Extendida - Versión 1.2.0 - Grupo Sauken S.A.

SFide-GUI proporciona una interfaz gráfica de usuario para asignar los parámetros adecuados a
cada una de las aplicaciones de la plataforma S-FiDE. Las aplicaciones se muestran de manera
independiente, elegibles desde el panel lateral de navegación. Estas aplicaciones también se
pueden ejecutar desde una línea de comando, lo que permite una sencilla integración con otras
aplicaciones pre-existentes. La salida de cada uno de estos procesos se despliega en el panel
"Salida del Proceso", donde se unifican la salida estándar y la de errores. Todas las entradas
y salidas de los procesos usan codificación UTF-8. Los procesos devuelven el control indicando
el resultado del mismo al programa que los ejecuta o bien al sistema operativo (0 es éxito,
1 es error).

## Aplicaciones disponibles

## 1. Ver Slots de Token (TokenSlotsView)
- Permite visualizar los slots disponibles en un token criptográfico
- Requiere biblioteca PKCS#11 y contraseña

## 2. Ver Certificados de Token (TokenCertificateExtractor)
- Extrae certificados digitales almacenados en un token criptográfico
- Requiere biblioteca PKCS#11, contraseña y número de slot

## 3. Ver Certificados PKCS#12 (PKCS12CertificateExtractor)
- Extrae certificados desde archivos PKCS#12 (.p12 o .pfx)
- Requiere archivo PKCS#12 y contraseña

## 4. Firmar XML con Token (XMLSignerPKCS11)
- Firma documentos XML usando un token criptográfico
- Requiere biblioteca PKCS#11, contraseña, número de slot, archivo XML y elemento a firmar
  (opcional)

## 5. Firmar XML con PKCS#12 (XMLSignerPKCS12)
- Firma documentos XML usando un archivo PKCS#12
- Requiere archivo PKCS#12, contraseña, archivo XML y elemento a firmar (opcional)

## 6. Verificar Firmas en XML (XMLVerifySignatures)
- Verifica la validez de firmas en documentos XML
- Requiere archivo XML firmado

## 7. Verificar XML con XSD (XMLVerifyXSDStructure)
- Valida documentos XML contra un esquema XSD
- Requiere archivo XML y archivo XSD (si no se referencia a uno dentro del XML)

## 8. Firmar PDF con Token (PDFSignerPKCS11)
- Firma documentos PDF usando un token criptográfico
- Requiere biblioteca PKCS#11, contraseña, número de slot, documento PDF, posición en ejes X e
  Y para colocar el cuadro con la firma digital, texto adicional para adjuntar a la firma y una
  opción que permite bloquear o no el documento PDF firmado

## 9. Firmar PDF con PKCS#12 (PDFSignerPKCS12)
- Firma documentos PDF usando un archivo PKCS#12
- Requiere archivo PKCS#12, contraseña, documento PDF, posición en ejes X e Y para colocar el
  cuadro con la firma digital, texto adicional para adjuntar a la firma y una opción que
  permite bloquear o no el documento PDF firmado

## 10. Verificar Firmas en PDF (PDFVerifySignatures)
- Verifica la validez de firmas en documentos PDF
- Requiere archivo PDF firmado

## 11. Ver Certificados de Windows (WindowsCertificateStoreView) - solo Windows
- Muestra los certificados disponibles en el almacén "Personal" de Windows: alias, sujeto
  (CN), emisor, vigencia, número de serie y si tiene clave privada
- No requiere ningún dato: se ejecuta con un solo clic en "Ejecutar"
- **Úsela antes de firmar** con las dos opciones siguientes si no conoce con exactitud el
  alias o el nombre (CN) del certificado que necesita — es el mismo rol que cumple
  "Ver Slots de Token" para un token PKCS#11, pero para el almacén de Windows

## 12. Firmar XML con Windows CSP/KSP (XMLSignerWindowsCSP) - solo Windows
- Firma documentos XML usando un certificado ya presente en el almacén de certificados de
  Windows (CSP/KSP), sin necesitar configurar una biblioteca PKCS#11
- Requiere el alias exacto o un fragmento del nombre (CN) del certificado, archivo XML y
  elemento a firmar (opcional). No pide contraseña: el acceso a la clave lo administra Windows
- Útil cuando el certificado de su token ya aparece en el Administrador de certificados de
  Windows. Para la mayoría de los casos, PKCS#11 sigue siendo la opción recomendada por ser
  estándar y multiplataforma; esta es una alternativa a elección del usuario

## 13. Firmar PDF con Windows CSP/KSP (PDFSignerWindowsCSP) - solo Windows
- Igual que el anterior, pero para documentos PDF. Admite las mismas opciones de posición,
  texto adicional y bloqueo del documento que "Firmar PDF con Token"

## Novedades en la versión 1.2.0

- **Validación de revocación antes de firmar**: los seis módulos que firman (aplicaciones 4, 5,
  8, 9, 12 y 13 de este listado) ahora consultan si el certificado está revocado ANTES de
  firmar, no solo al verificar una firma ya hecha. Si el certificado está confirmado como
  revocado, no se firma - la interfaz gráfica nunca ofrece forma de forzarlo
- **Si no se puede determinar el estado** (por ejemplo, sin conexión a Internet): en Firmar
  XML/PDF con PKCS#12 y con Windows CSP/KSP (aplicaciones 5, 9, 12 y 13), aparece un diálogo
  preguntando si desea firmar de todas formas. En Firmar XML/PDF con Token (aplicaciones 4 y 8)
  no aparece ningún diálogo, se avisa por el panel de salida y se firma igual - para no arriesgar
  un segundo ingreso de PIN al token físico
- **Nuevo ítem de menú "Herramientas > Recrear accesos directos"** (Windows): recrea a pedido
  los accesos directos del escritorio y el menú inicio, apuntando a esta instalación. Útil
  después de actualizar S-FiDE a una carpeta nueva, o si borró alguno sin querer. El acceso
  directo a la aplicación ya no lleva el número de versión en el nombre (antes sí) - así, al
  actualizar de versión, el primer arranque de la versión nueva reemplaza directamente el ícono
  de la versión anterior en vez de sumar uno más al lado
- **Nueva pestaña "Documentación" en esta ventana de Ayuda**: abre, con un clic, la Guía de
  Usuario y el Manual Técnico en el navegador predeterminado. La pestaña "Contacto" ahora
  incluye también un enlace a la página del proyecto en GitHub
- **Instancia única**: si ya hay una ventana de S-FiDE abierta desde esta misma carpeta y se
  intenta abrir otra, se avisa y esa segunda ventana se cierra sola, sin afectar a la que ya
  estaba abierta. Instalaciones en carpetas distintas sí pueden correr en paralelo
- **Nuevo botón "Abrir documento generado"** junto al documento de entrada, en las seis
  pestañas de firma: se habilita solo cuando la firma termina bien y el archivo firmado
  ("-signed") realmente existe, y lo abre en el navegador con un clic
- **Nuevo botón de ayuda ("?")** junto a "Elemento XML (ID) a Firmar" y junto a la posición
  X/Y de firma en PDF, con una explicación detallada de cada campo - la de posición incluye
  las coordenadas recomendadas para comercio exterior (Exportador y Funcionario Habilitado)
- Los campos vacíos ahora muestran un ejemplo de carga en gris claro (no es un valor real)
- **"Salida simple"** de los verificadores ahora se recuerda entre sesiones. La posición X/Y
  de firma en PDF y "Bloquear documento después de firmar" dejaron de recordarse y de
  compartirse entre pestañas - siempre hay que indicarlas de nuevo en cada firma

## Novedades en la versión 1.1.1

- **Panel lateral de navegación**, en reemplazo de la antigua barra de pestañas horizontal
- **Detección de driver PKCS#11**: en los módulos que usan una biblioteca PKCS#11, un botón
  "Detectar automáticamente" revisa las rutas típicas conocidas (SafeNet, ePass2003, mToken
  CryptoID, Athena) e indica cuál está instalada en su equipo. También puede elegir la
  marca/modelo manualmente en la lista desplegable, que completa la ruta por usted
- **Compatibilidad ampliada de tokens PKCS#11**: los módulos de firma ahora prueban
  automáticamente un mecanismo de firma alternativo si el token no admite el mecanismo
  combinado habitual (por ejemplo, tokens tipo ePass2003), sin necesidad de configuración
  adicional de su parte
- **Alternativa de firma con el almacén de certificados de Windows (CSP/KSP)**, ver
  aplicaciones 12 y 13 arriba, y su visor dedicado (aplicación 11)
- La ruta de biblioteca PKCS#11/PKCS#12, el número de slot, el alias del almacén de Windows,
  el último módulo abierto, el tamaño de la ventana y algunas preferencias de firma de PDF
  ahora se recuerdan entre sesiones (ver "Preguntas Frecuentes")
- (Windows) La primera vez que ejecuta SFide-GUI.bat en una instalación, se crean
  automáticamente accesos directos en el escritorio y en el menú inicio, con ícono propio: uno
  a la aplicación y dos más que abren en el navegador la Guía de Usuario y el Manual Técnico

## Requerimientos

- OpenJDK 23 o superior
- JavaFX 23 o superior (solo para esta aplicación con interfaz gráfica)
- Biblioteca PKCS#11 del token (para funciones relacionadas con tokens)
- Biblioteca iText 8 o superior (para funciones relacionadas con documentos PDF)
- Permisos de lectura en los archivos a procesar
- Permisos de escritura en las carpetas de salida
- Permiso de lectura y ejecución de la biblioteca PKCS#11 del token

## Notas

- Los archivos de salida se generan en el mismo directorio que los archivos de entrada
- Mantenga sus certificados y contraseñas en lugar seguro. No los comparta
- Asegúrese de tener copias de respaldo de los archivos antes de procesarlos
- **Cuidado con los tokens criptográficos:** un número elevado de intentos de acceso fallido
  (contraseña inválida) puede dejar inutilizada su firma digital, por lo que deberá concurrir
  a solicitar una nueva a una autoridad certificante (AC). Esto **no** aplica a las
  aplicaciones que usan el almacén de Windows (CSP/KSP), donde el PIN lo administra Windows
- Por línea de comandos, las aplicaciones que trabajan con tokens PKCS#11 aceptan el parámetro
  "-listar-drivers" (o "--listar-drivers" en PDFSignerPKCS11) para ver las rutas típicas de
  driver conocidas para su sistema operativo
