XMLVerifyXSDStructure - Programa que verifica si un archivo XML cumple con las especificaciones contenidas en un archivo XSD

USO
  Un documento:
    java -jar XMLVerifyXSDStructure.jar <Archivo XML> [<Archivo XSD>]
  Por lote (una lista de documentos, desde 1.6.0):
    java -jar XMLVerifyXSDStructure.jar -lote <lista> [<Archivo XSD>] [-informe <archivo.csv>] [-log]
  Información:
    java -jar XMLVerifyXSDStructure.jar -version | -ayuda | -licencia

  -version, -v, --version      Muestra la versión del programa
  -ayuda, -h, --help           Muestra este mensaje de ayuda
  -licencia, --license         Muestra la información de licencia

PARÁMETROS DE LOS DOS MODOS
  <Archivo XSD>           Opcional. Esquema contra el que se valida. Si no se indica, se usa el esquema que
                          declara cada documento XML (se descarga de Internet)

SOLO PARA UN DOCUMENTO
  <Archivo XML>           Documento a validar. Va antes del esquema

SOLO POR LOTE
  -lote <lista>           Tiene que ser el primer argumento. <lista> es un archivo de texto en UTF-8 con la ruta
                          de un documento por línea; las rutas relativas se toman desde la carpeta de la lista
  <Archivo XSD>           Si se indica, va inmediatamente después de la lista y vale para todos los documentos.
                          Si no, cada esquema declarado se descarga una sola vez por lote
  -informe <archivo.csv>  Genera un informe (campos separados por punto y coma, UTF-8) con una línea por
                          documento. Reemplaza un informe anterior; no puede terminar en .xml ni .pdf
  -log                    Guarda junto a cada documento un archivo <documento>.log con el detalle de su
                          validación y su resultado. Si el archivo existe, agrega al final

  Ejemplos de lotes correctos y con errores: doc/guia-lotes-integradores.html, en la carpeta de S-FiDE.

SALIDA Y CÓDIGO DE SALIDA
  Un documento: muestra la validación de la estructura y de las firmas. Código 0 si la estructura cumple el
  esquema y las firmas son correctas; 1 en cualquier otro caso (incluido un documento sin firmas).
  Por lote: por la salida estándar, las líneas LOTE_INICIO, LOTE_DOC (una por documento) y LOTE_RESUMEN, con
  campos entre comillas separados por punto y coma; un programa debe procesar solo las líneas que empiezan con
  LOTE_. Los problemas salen también por la salida de error. El detalle de cada documento no se muestra: queda
  en su archivo .log. Código 0 solo si no se detuvo el lote y todos los documentos terminaron bien. Estados y
  códigos: Manual Técnico de Integración, sección 7.11.
  Este programa no comprueba la revocación de los certificados (para eso, XMLVerifySignatures).

EJEMPLOS
  Un documento:
    java -jar XMLVerifyXSDStructure.jar certificadoorigen-signed.xml
    java -jar XMLVerifyXSDStructure.jar certificadoorigen-signed.xml cod_ver_1.8.2.xsd
  Por lote:
    java -jar XMLVerifyXSDStructure.jar -lote lista.txt -informe informe.csv
    java -jar XMLVerifyXSDStructure.jar -lote lista.txt cod_ver_1.8.2.xsd -log

MARCA BOM EN EL XML (desde 1.5.0)
  Si el XML comienza con una marca BOM (tres bytes invisibles que algunos editores agregan al guardar en UTF-8),
  el programa lo informa y la ignora para verificar: no afecta el resultado de las firmas. El archivo no se
  modifica. Un XML guardado en UTF-16 se rechaza con un mensaje: debe volver a guardarse como UTF-8.
