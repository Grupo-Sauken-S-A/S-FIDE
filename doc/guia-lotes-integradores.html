Operaciones por lotes

Cómo firmar, verificar y validar muchos documentos en una sola ejecución desde su propio sistema: reglas, contrato de salida y ejemplos de cada programa, con y sin errores.

Versión del producto: 1.6.0
01

Objetivo y alcance

El trabajo por lotes permite aplicar una misma operación a una lista de documentos en una sola ejecución de un programa de S-FiDE. Está pensado para quien integra S-FiDE desde su propio sistema y hoy invoca el programa una vez por documento.

Qué resuelve

  • Un solo acceso al certificado por lote: un ingreso de contraseña o PIN y una sola consulta de revocación, en lugar de uno por documento.
  • Un resultado estable por documento (estado, código y mensaje), pensado para que lo procese un programa.
  • Un resumen del lote y un código de salida que dice si todo terminó bien.
  • Informe CSV y registro por documento, opcionales.
  • En la firma, una revisión previa sin usar el certificado.

Compatibilidad

Invocar un programa sin -lote funciona como en el modo de un documento. El lote es una forma adicional de uso.

Sobre los ejemplos

Las salidas de esta guía se obtuvieron ejecutando los programas de la versión 1.6.0 en Windows, con documentos y un certificado de prueba creados para este fin (contraseña de ejemplo: clave-de-ejemplo). La carpeta de trabajo se muestra como C:\lotes. Los pocos ejemplos que no se pudieron ejecutar (firma con un token físico) están señalados como ilustrativos.

En los comandos se escribe java -jar Programa.jar. S-FiDE trae su propio Java: en una instalación en C:\S-FiDE es C:\S-FiDE\openjdk-23.0.1\windows-x64\bin\java.exe.

02

Reglas y restricciones

Una sola operación por lote

  • Todos los documentos reciben exactamente la misma operación con los mismos parámetros. No se pueden indicar opciones por documento.
  • Firma XML: se firma un único elemento (o el documento completo) y no se mezclan tipos de documento. Ante una mezcla no se firma ninguno.
Elemento pedidoTodos los documentos deben ser
COD, CODEHCertificados de Origen Digital
DJO, DJOEHDeclaraciones Juradas de Origen
"" (documento completo)XML que no sean de comercio exterior
Otro identificadorDel mismo tipo que el primer documento legible de la lista
  • Firma PDF: misma página, posición, tamaño, texto y opciones para todos. Si se pide cerrar, se cierran todos. -campo no se admite.
  • Para dos firmas distintas (por ejemplo COD y luego CODEH) se ejecutan dos lotes: el segundo con la lista de los archivos generados por el primero.

Archivos generados

  • El firmado se guarda junto al original como nombre-signed.extensión. El original no se modifica.
  • Por lote nunca se reemplaza un archivo que ya exista: el documento queda OMITIDO / SALIDA_YA_EXISTE y el código de salida es 1. (De a un documento, en cambio, se reemplaza.)
  • Se escribe primero un archivo temporal (.tmp-sfide) y recién al final toma su nombre definitivo. Si se mata el proceso, puede quedar un temporal que se puede borrar.

Argumentos

  • En los programas de argumentos por posición (firmadores XML, verificadores y validador XSD), -lote es el primer argumento. En los firmadores PDF va en cualquier posición y reemplaza a -i.
  • Por lote los argumentos son estrictos: uno desconocido, repetido, incompleto o no admitido detiene todo antes de empezar (ARGUMENTOS).
  • -revisar solo vale junto con -lote; sin él es un error y no se firma.
  • Opciones: -lote, -informe, -log y -revisar se aceptan con uno o dos guiones.

Certificado y token

  • Se accede al certificado una sola vez y solo si queda algún documento por firmar.
  • Una contraseña o PIN incorrecto nunca se reintenta.
  • Un certificado vencido, todavía no válido, no apto para firmar o revocado detiene el lote.
  • No se deben ejecutar dos lotes a la vez con el mismo token.
  • Algunos tokens pueden pedir el PIN en cada firma por una política propia: conviene probar con el token real antes de automatizar.
03

Cómo se ejecuta un lote

  1. Se controlan los argumentos.
  2. Se lee la lista. Si no se puede leer o está vacía, se detiene.
  3. Se crea el informe, si se pidió. Si no se puede, no se procesa nada.
  4. Se revisa cada documento sin usar el certificado: existencia, extensión y formato; en la firma, además, archivo de salida existente, elemento o firmas previas requeridas (XML), documento cerrado, página y posición (PDF). En XML se controla que no haya mezcla.
  5. En la firma, se accede al certificado una vez: vigencia, aptitud y revocación.
  6. Se procesa documento por documento. Se informa cada resultado apenas se conoce.
  7. Se informa el resumen y el código de salida.

Qué detiene todo el lote y qué no

Detiene el lote (lo pendiente queda NO_PROCESADO)No lo detiene (afecta solo a ese documento)
Argumentos, lista o informe inválidos; mezcla de tipos; biblioteca, token o contraseña; certificado no apto o revocado; archivo XSD indicado que no existe; 3 errores seguidos de acceso a la claveDocumento inexistente, dañado, repetido, con otra extensión, ya firmado, cerrado, sin el elemento pedido o con salida existente; firma no válida al verificar

La lista de documentos

  • Archivo de texto en UTF-8 (con o sin BOM). En otra codificación se rechaza completo.
  • Una ruta por línea. Las rutas relativas se resuelven desde la carpeta de la lista.
  • Se quitan los espacios de los extremos y las comillas que envuelvan la ruta. Las líneas vacías se ignoran. El tabulador está reservado.
  • Un documento repetido se informa OMITIDO / DUPLICADO la segunda vez.
  • Todos deben tener la extensión del programa (.xml o .pdf).
04

Salidas, estados y código de salida

Salida estándar

Texto en UTF-8. Las líneas del lote empiezan con LOTE_; los campos van entre comillas y separados por punto y coma (una comilla dentro de un campo se duplica).

LOTE_INICIO;"1";"programa";"versión";"total"
LOTE_DOC;"n";"total";"estado";"código";"entrada";"salida";"log";"mensaje"
LOTE_RESUMEN;"total=…";"correctos=…";"con_avisos=…";"no_validos=…";"sin_firmas=…";"con_error=…";"omitidos=…";"no_procesados=…";"corte=…"
  • El 1 de LOTE_INICIO es la versión del formato.
  • Leída la lista, cada documento tiene exactamente una línea LOTE_DOC.
  • corte=NINGUNO si el lote no se detuvo.
  • También pueden aparecer avisos generales (revocación, reloj, certificado): procesar solo las líneas que empiezan con LOTE_.
  • Sin LOTE_RESUMEN, el lote está incompleto (por ejemplo, porque se cortó el proceso).

Salida de error

La causa de un corte (Error: …) y una línea archivo: mensaje por cada documento con problema. Hay que leer las dos salidas a la vez para que el proceso no quede bloqueado.

Estados

Código de salida del proceso

0 solo si el lote no se detuvo y todos los documentos terminaron en un estado que da código 0. En cualquier otro caso, 1. Un 0 puede incluir avisos: si importan, leer los estados.

Informe CSV (-informe archivo.csv)

Columnas n;total;estado;codigo;entrada;salida;log;mensaje, con encabezado, UTF-8 sin BOM. Se escribe línea por línea. No puede terminar en .xml ni .pdf, ni ser la lista; un informe anterior se reemplaza.

Registro por documento (-log)

Junto a cada documento queda documento.extensión.log, que se entiende solo: encabezado, avisos generales del lote, lo mismo que se vería al procesar ese documento solo (incluido el error) y la línea Resultado:. Si ya existe, se agrega al final. No se genera para los NO_PROCESADO ni con -revisar. Nunca incluye la contraseña.

Revisión previa (-revisar, solo firmadores)

Ejecuta las comprobaciones que no necesitan el certificado e informa cada documento como LISTO, OMITIDO o ERROR. No firma ni escribe documentos. Hay que escribir los mismos argumentos que para firmar; la contraseña puede ser "" y no se usa. No comprueba la biblioteca, el token, el archivo del certificado ni la contraseña.

05

Cómo integrarlo

Secuencia recomendada

  1. Generar la lista en UTF-8 con los documentos pendientes.
  2. Opcional, al firmar: ejecutar con -revisar y apartar lo que no esté LISTO.
  3. Ejecutar el lote con -informe (y -log si se quiere el detalle).
  4. Mirar el código de salida. Si es 1, leer el informe o las líneas LOTE_DOC.
  5. Para repetir, armar la lista solo con lo pendiente: lo ya firmado daría SALIDA_YA_EXISTE y código 1.
  6. Si el corte fue por la contraseña o el token, corregir antes de volver a ejecutar: no reintentar en forma automática.

Recomendaciones

  • No fijar un tiempo máximo corto: un lote grande, o una consulta de revocación lenta, pueden tardar varios minutos.
  • La contraseña viaja como argumento y puede verse en la lista de procesos del sistema: tenerlo en cuenta en equipos compartidos.
  • Poner entre comillas las rutas con espacios.
  • Leer todo en UTF-8.

Ejemplo en PowerShell

$java = 'C:\S-FiDE\openjdk-23.0.1\windows-x64\bin\java.exe'
$jar  = 'C:\S-FiDE\XMLVerifySignatures.jar'
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

$salida = & $java -jar $jar -lote verificar.txt -informe informe.csv
$codigo = $LASTEXITCODE

if (-not ($salida -match '^LOTE_RESUMEN;')) { Write-Output 'Lote incompleto'; exit 1 }

$columnas = 'n','total','estado','codigo','entrada','salida','log','mensaje'
$documentos = $salida | Where-Object { $_ -like 'LOTE_DOC;*' } |
    ForEach-Object { $_.Substring(9) } |
    ConvertFrom-Csv -Delimiter ';' -Header $columnas

foreach ($d in $documentos) {
    $nombre = Split-Path $d.entrada -Leaf
    Write-Output ('{0} {1} {2} {3}' -f $d.n, $d.estado, $d.codigo, $nombre)
}
Write-Output "Codigo de salida: $codigo"
exit $codigo

Ejemplo en Linux o macOS

#!/bin/sh
JAVA=/opt/S-FiDE/openjdk-23.0.1/linux-x64/bin/java
JAR=/opt/S-FiDE/XMLVerifySignatures.jar

"$JAVA" -jar "$JAR" -lote verificar.txt -informe informe.csv > salida.txt 2> errores.txt

grep -q '^LOTE_RESUMEN;' salida.txt || { echo "Lote incompleto"; exit 1; }

echo "Documentos con problemas:"
grep -E '^LOTE_DOC;"[0-9]+";"[0-9]+";"(ERROR|NO_VALIDO|SIN_FIRMAS|NO_PROCESADO|OMITIDO)";' salida.txt
echo "Codigo de salida: $codigo"
exit $codigo

Cómo generar la lista

PowerShell (solo los XML que todavía no están firmados):

Get-ChildItem C:\lotes\*.xml | Where-Object { $_.BaseName -notlike '*-signed' } |
    ForEach-Object { $_.FullName } | Set-Content -Encoding utf8 C:\lotes\lista.txt

Símbolo del sistema (.bat): ejecutar chcp 65001 antes, para que los acentos queden en UTF-8.

chcp 65001 > nul
(for %%F in (C:\lotes\*.pdf) do @echo %%F) > C:\lotes\lista.txt

Linux o macOS:

find /srv/lotes -maxdepth 1 -name '*.xml' ! -name '*-signed.xml' | sort > lista.txt

Sintaxis por lote
java -jar PDFSignerPKCS11.jar -lote <lista> -l <biblioteca> -p <contraseña> -s <slot> [-k true|false] [-x n] [-y n] [-pagina n] [-ancho n] [-alto n] [-t texto] [-proteger-contenido true|false] [-omitir-revocacion true|false] [-revisar] [-informe <archivo.csv>] [-log]
ArgumentoDescripción
-loteReemplaza a -i
-lBiblioteca PKCS#11 (atención: en PDFSignerPKCS12, -l significa cerrar)

-proteger-contenidoNo se combina con -k

Las reglas sobre documentos son las mismas que en PDFSignerPKCS12; sus ejemplos 3 a 8 y 10 a 12 valen igual, cambiando -l por -k. Además admiten -informe y -log.
